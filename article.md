# RecallDesk: customer support that remembers what worked

Ticket history is necessary, but it is a poor substitute for experience. A repeat customer should not have to endure the same failed troubleshooting sequence simply because a previous agent’s resolution is buried in an old conversation. RecallDesk is a support workspace designed around that gap: it gives an agent durable, customer-scoped memory of outcomes, constraints, and preferences.

Its primary demo follows Aarav Mehta at NovaStack. A past CloudSync synchronization incident established three useful facts: reinstalling CloudSync failed, clearing the cache failed, and reconfiguring the network resolved the issue. Aarav also prefers concise troubleshooting and does not want failed steps repeated. On a later ticket, RecallDesk sends the ticket query and Aarav’s customer identifier to Hindsight. The resulting memories are shown in the workspace and passed directly into the drafting context. The agent’s response therefore starts from the previous network fix rather than presenting a generic checklist.

That change is more important than a retrieval card. The memory has to alter the action. When Aarav adds that he is on different Wi-Fi, the agent combines the historical successful fix with this new context and recommends refreshing network configuration. Once confirmed, the outcome is retained in Hindsight. A future network-switch ticket can retrieve that newer experience as well.

The implementation keeps the memory boundary on the server. The browser calls a small RecallDesk API, which validates the customer identifier and calls Hindsight with server-only credentials. Each operation includes customer metadata so customer memories can be isolated. The same browser submits the resulting memory context to an agent drafting endpoint; the product never exposes API keys or internal reasoning. Observable activity—recall started, memories found, response generated, retain completed—makes the workflow legible without exposing chain of thought.

RecallDesk is deliberately focused. It is not a generic chatbot or a new vector database. The product’s value comes from treating support outcomes as reusable experience and making that experience visible at the moment an agent needs it. That means fewer repeated dead ends, a more respectful customer experience, and a support system that improves one resolved ticket at a time.
